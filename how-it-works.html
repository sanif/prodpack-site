THE WIZARD, START TO FINISH

From an empty folder to a locally running SaaS repo, in one wizard.

Six steps take you from a preset to a composed, validated repository, then bootstrap a local app. Selected Docker, CI, and environment files prepare the repository for deployment, while you keep control of provider accounts, credentials, DNS, and production rollout.

Empty folder→Composed, secured repo→Local app running→Deploy-ready files
1

Pick a template

Tell ProdPack what you are building. It starts you from a preset and assembles a sensible starting set of modules that you tune from there, so you are never staring at a blank configuration.

Preset, not a blank slate
prodpack · step 1 of 6
2

Name your project

A few details so ProdPack scaffolds in the right place: the project name, where it lives on disk, and the conventions every generated file will follow.

Scaffolded in the right place
prodpack · step 2 of 6
3

Choose your modules

This is the heart of ProdPack. Toggle the features your product needs: auth, billing, teams, flags, observability, storage. Dependencies resolve automatically and conflicts are caught before a single line is written.

Composition over scaffolding. Capability rules resolve compatible providers and surface conflicts before generation. Each pack also carries a maturity label that states how far it has been verified.
prodpack · step 3 of 6
4

Configure each pack

Set per-pack options to fit your product. Secrets are generated at this step and written straight to a gitignored .env, never committed to the repo.

Security-first by default. A 64-byte JWT secret and other keys are generated for you, kept out of version control from the first commit.
prodpack · step 4 of 6
5

See it compose

A live composition map shows how every module assembles onto the skeleton: which module owns and patches each file, where any conflicts are, and the branched migration graph. Click any file to preview the exact code that will be generated, attributed to the module that produced it, before you commit. No surprises after you press generate.

See it before it is written
prodpack · step 5 of 6
6

Generate, set up, and run locally

One click runs the documented local setup, including dependencies, the database, migrations, and bootstrap data, then starts the app. ProdPack stays resident in your menu bar so you can start, monitor, and stop generated projects. When selected, Docker, CI, environment, and provider-specific release files are generated for your review. You still provision infrastructure and complete the production deployment.

Ready for your coding agent. Plain-markdown project guidance and reusable workflows can be used with Claude Code, Cursor, Copilot, and other agents. The included security review runs when you invoke it.
